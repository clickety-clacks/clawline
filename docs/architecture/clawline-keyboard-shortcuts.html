Clawline Keyboard Shortcut Inventory

This document is the primary product authority for Clawline keyboard shortcuts: what shortcuts exist, what they do, where they apply, and how conflicts resolve. Ticket specs and historical tracker notes are provenance only unless this document links or incorporates their behavior.

Product rule: this document owns Clawline shortcut product truth. The unified keyboard router is the implementation architecture that enforces this contract. Platform hooks normalize key events and report context; they do not invent precedence or own product behavior locally.

Precedence rule: transient explicit surfaces win first, notification-global commands win over focused text fields when listed here, text fields own ordinary text editing, and transcript/chat scrolling receives only unclaimed keys.

Review rule: every keyboard-related ticket review must receive this document as a source-of-truth artifact and mark each affected shortcut contract as satisfied, unsatisfied, unproven, or out-of-scope.

Implementation state: every shortcut family in this inventory is expected to have an implementation path today except vim-mode suggestion keys, which remain planned until T314 implementation ships.

Platform Notes

  • On iOS/iPadOS, notification shortcut numbers are visible only when hardware-keyboard availability is detected.
  • On macOS/Catalyst, hardware-keyboard shortcuts are assumed available unless the platform reports otherwise.
  • On web, browser/system-owned conflicts remain unsupported where the browser cannot safely expose the shortcut.
  • Platform bridges may need responder-layer capture for UIKit/AppKit/Web, but they remain bridges. The router remains the policy authority.

Open Risks

  • Font-scale conflicts: font scale uses Cmd-+ to increase, Cmd-- to decrease, and Cmd-0 to reset to 100%. Notification clear-all uses Cmd-Shift-Option--, matching the assigned-notification dismiss family. Cmd-0 also opens the assigned notification action menu for slot 0 and still needs explicit router proof.
  • Drift risk: new SwiftUI keyboardShortcut, UIKit responder overrides, or web onKeyDown handlers can bypass the router. Reviews for keyboard work must check this document plus T343.
  • Inventory gap: older archived shortcuts may exist outside active specs. When found, add them here with source and conflict notes rather than treating tickets as the long-term inventory.
