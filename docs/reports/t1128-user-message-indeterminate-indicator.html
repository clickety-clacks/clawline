T1128: User Message Bubble Indeterminate Indicator

Investigation/report only. Prepared 2026-05-23 and continued 2026-05-23 22:53 PDT from the Clawline source tree and shared workspace docs. No code changes, deploy, merge, restart, cleanup, or rehome were performed for T1128.

Executive Summary

R1128-01 The bottom-right indeterminate indicator on native user message bubbles represents a locally-created outbound user message that has been handed to Clawline's send pipeline but has not yet received provider ack for its client message id.

R1128-02 On iOS and Mac Catalyst, the visual is a 24 x 24 badge positioned at the bubble's bottom-right edge. Pending state uses a UIActivityIndicatorView; failure state reuses the same badge location with an exclamation button and a resend menu.

R1128-03 The indicator disappears when the local message is accepted by provider ack, replaced by the provider's echoed user message, canceled before transport send, removed by teardown/logout/history reset, or converted to a failed resend affordance.

R1128-04 This is not the assistant typing indicator, live agent progress, attachment loading spinner, stream-manager progress row, or web text footer. Those are overlapping progress surfaces with different state machines.

Product Model

R1128-07 The product contract in docs/ios-provider-connection.md says client messages use client ids like c_123; provider-assigned durable events use s_*; the provider echoes accepted user messages to all devices with clientMessageId; and the client should keep a message in a sending state until provider ack arrives.

R1128-08 In implementation terms, native Clawline creates an optimistic local user Message whose id is the c_* client id. That id is added to pendingLocalMessages. While it is present there and absent from ackedPendingLocalMessageIDs, sendIndicatorState(for:) returns .pending.

R1128-09 Provider ack is acceptance/durability, not assistant completion. The spinner is expected to clear before the assistant's final answer if ack arrives first. The later assistant typing/live-progress surface is separate.

Spec Gaps and Unproven Behavior

  • G1128-01 Spec/implementation mismatch: docs/ios-provider-connection.md:162 says no ack after 5 seconds should cause resend with the same id and pending ids should persist after relaunch. Current native tests explicitly say Chat send does not automatically retry an unacked message, and native state stores pending send bookkeeping in memory. This report does not resolve which is current product authority.
  • G1128-02 Ack-only lifetime after app relaunch is unproven for native. If a message is acked but the app exits before the echo, current source evidence does not prove the exact UI after relaunch.
  • G1128-03 No explicit product spec was found for the native badge's exact placement, size, color, or whether it should be visible at all after transport send starts but before ack. The implementation and tests prove current behavior; product acceptance should confirm visual intent.
  • G1128-04 Electron-specific behavior is unproven. The web code has text status, but no separate Electron runtime indicator override was proven.
  • G1128-05 Provider ordering edge case is implementation-defined in this report. The client handles ack before echo and echo before ack, but this report did not prove provider ordering guarantees beyond the documented protocol semantics.

Answer to Flynn's Question

A1128-01 It appears when a user send has passed local validation and Clawline has inserted the optimistic c_* user bubble, but the provider has not yet acknowledged that c_* id.

A1128-02 It disappears when provider ack marks that client id accepted, when the provider's echoed user message replaces the optimistic bubble, when the send is canceled before transport, or when the pending send becomes a failure/retry state.

A1128-03 It does not mean the assistant is still thinking. After ack, assistant activity is represented by the assistant typing indicator, session status/live progress, and eventual assistant message stream, not by the user-bubble spinner.
