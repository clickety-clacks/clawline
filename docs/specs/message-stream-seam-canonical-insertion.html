T105 Message Stream Seam Canonical Insertion Protocol

Clawline iOS shared spec. Prepared 2026-05-27. Canonical artifact: /Users/mike/shared-workspace/clawline/specs/message-stream-seam-canonical-insertion.html.

Decision: every Clawline iOS message stream mutation must go through one canonical insertion and mutation seam.

T105 stays separate from T100. T100 owns connection phases, replay admission, reconnect, and cache/replay lifecycle barriers. T105 owns the in-memory message mutation authority after a caller has a message operation to apply.

Source Basis

  • Tracker T105 goal: define and implement a single canonical mutation seam for the iOS chat message stream. Network, cache, and input sources funnel through one write path with deterministic deduplication, conflict resolution, and ordering.

Goal

T105-GOAL-01 Make message insertion, update, cache restore, removal, session clearing, session deletion, retry, and logout clearing deterministic by routing them through one seam.

T105-GOAL-02 Prevent duplicate messages, cache overwrites of live messages, wrong-stream placeholders, stale cursor references, and direct write bypasses.

Non-Goals

  • T105-NG-01 This spec does not redesign message bubble UI, markdown rendering, scrolling, stream switching, notifications, or provider connection lifecycle.
  • T105-NG-02 This spec does not require provider wire protocol changes unless the existing data is insufficient for a listed requirement.
  • T105-NG-03 This spec does not allow optimistic placeholder creation before send admission is satisfied.
  • T105-NG-04 This spec does not expose arbitrary full-session replacement as a public caller operation.

Operation Vocabulary

ID Operation Caller Intent
T105-OP-01 upsert Insert a new message ID or update an existing message ID in place.
T105-OP-02 remove Remove one message by ID within its owning session.
T105-OP-03 cacheGapFill Insert cache-restored IDs that are absent from the current session set.
T105-OP-04 clearSessionMessages Clear messages while preserving stream/session metadata.
T105-OP-05 removeSession Remove the session and associated cursor state.
T105-OP-06 clearAllForLogout Atomically clear all message, selection, cursor, pending, and failure state for logout.

Requirements

T105-REQ-01 Single Writer

All production message collection mutations must route through the seam. Direct writes to sessionMessages or equivalent per-session message arrays/dictionaries are prohibited outside the seam implementation and its tests.

T105-REQ-02 Compiler-Error-First Migration

Implementation must delete, mark unavailable, or otherwise make legacy direct-write APIs fail before routing callers through compatibility wrappers. The migration list must come from compile errors, not from a guessed call-site inventory.

T105-REQ-03 Public Operations Are Bounded

Callers must express intent through the bounded operations in this spec. replaceSession, if needed, is internal seam machinery only and must not be available as a public caller operation.

T105-REQ-04 Deduplication By Session And ID

The seam deduplicates by (sessionKey, id). A message ID collision in one session must not affect another session.

T105-REQ-05 Existing IDs Update In Place

For an existing message ID in the same session, upsert updates the existing entry in place. Repeated server events for the same streaming message ID must update one entry rather than append duplicates.

T105-REQ-06 New IDs Use Canonical Ordering

For a new message ID, upsert inserts according to the seam's canonical ordering rule. Callers must not directly reorder the message collection outside the seam.

T105-REQ-07 Cache Is Gap-Fill Only

Cache-restored messages may insert only IDs absent from the current session set. Cache restore must not delete, reorder, or overwrite an existing ID. If live replay has already supplied a message ID, later cache restore for that ID is a no-op for stream state.

T105-REQ-08 Server Wins On Conflict

When server-sourced and cache-sourced facts conflict for an existing ID, the server-sourced entry wins. Cache is not an update source after a live/server entry exists.

T105-REQ-09 Retry Appends At Tail

Retry of a failed message uses a new client ID and appends at the tail through the normal seam path. Retry must not reuse the original bubble position or original client ID.

T105-REQ-10 Provisioning Gate

The composer may create/send local placeholders only when transport is connected and the active session key is present in provisionedSessionKeys. canSend must require both conditions. No optimistic placeholder may be created before this gate passes.

T105-REQ-11 Clear Session And Remove Session Are Distinct

clearSessionMessages removes messages while preserving stream/session metadata. removeSession removes the session and associated cursor state. Implementations must keep these effects distinct.

T105-REQ-12 Logout Clear Is Atomic

clearAllForLogout must reset all per-session message collections, active engine session key, active UI-selected session key, global and per-session reconnect cursor state, pending local message tracking, and message failure tracking as one logout clear operation.

T105-REQ-13 Ongoing Enforcement

The implementation must include tests or static checks that fail when production code mutates the message collection outside the seam. Enforcement must allow seam internals and test fixtures while catching new direct production writes.

T105-REQ-14 Ordering Ambiguity Requires Clarification

If implementation encounters an ordering conflict not covered by existing model fields, it must request product or architecture clarification before inventing a new heuristic.

Acceptance Checks

  • T105-AC-01 A code search or static check shows no production direct mutations to sessionMessages outside the seam.
  • T105-AC-02 Upserting the same (sessionKey, id) twice updates one existing entry and does not append a duplicate.
  • T105-AC-03 Streaming repeated server events for the same message ID update one message entry.
  • T105-AC-04 The same message ID in two different sessions is treated as two independent session-scoped entries.
  • T105-AC-05 Cache restore after live replay does not overwrite, delete, or reorder live messages.
  • T105-AC-06 Cache can insert a missing message ID without replacing existing server-sourced IDs.
  • T105-AC-07 Retry of a failed message creates a new client ID at the tail through the seam.
  • T105-AC-08 Composer send admission remains blocked until both connected transport and active-session provisioning are true.
  • T105-AC-09 clearSessionMessages and removeSession have distinct tested effects on metadata and cursor state.
  • T105-AC-10 Logout clear removes all message/session/cursor/pending/failure state atomically.
  • T105-AC-11 Build, tests, or static checks fail if a new production direct-write path bypasses the seam.

Implementation Handoff

  1. T105-HO-01 Introduce or identify the seam interface and make legacy direct-write APIs unavailable first.
  2. T105-HO-02 Use the resulting compile failures to enumerate and migrate live/replay insert, cache restore, optimistic placeholder, pending-to-server replacement, attachment hydration, no-reply append, stream deletion, and logout clear call sites.
  3. T105-HO-03 Do not preserve broad compatibility wrappers that allow new direct writes.
  4. T105-HO-04 Keep this seam coherent with T103 per-stream runtime state and T100 connection lifecycle replay/cache behavior.

Open Questions

  • T105-OQ-01 If the current message model cannot express a deterministic ordering conflict, which existing source field should become authoritative: provider sequence, timestamp, receive order, or another explicit field?
  • T105-OQ-02 Should direct-write enforcement be a unit/static test in the iOS test target, a repository script, or both?
