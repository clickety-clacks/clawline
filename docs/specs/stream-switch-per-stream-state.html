T103 Stream Switch and Per-Stream State

Clawline iOS shared spec. Prepared 2026-05-27. Canonical artifact: /Users/mike/shared-workspace/clawline/specs/stream-switch-per-stream-state.html.

Decision: stream switching must be governed by a per-stream runtime state contract, not by controller-global reset behavior.

T103 stays separate from T100. T100 owns provider connection lifecycle, replay, reconnect admission, and cache/replay barriers. T103 owns visible stream activation, scroll persistence, scroll-to-bottom state, deferred UI work, and per-stream runtime state keyed by sessionKey.

Goal

T103-GOAL-01 Switching into a Clawline stream lands at that stream's persisted scroll position when one exists, otherwise at bottom.

T103-GOAL-02 State from one stream must not leak into another stream through reused controller instances, debounce timers, scroll callbacks, pending auto-scroll work, restore phase, typing state, morph state, unread state, or size caches.

Non-Goals

  • T103-NG-01 This spec does not redesign the connection lifecycle state machine, reconnect policy, or provider replay protocol.
  • T103-NG-02 This spec does not change message rendering, markdown parsing, bubble visual design, or stream selector UI.
  • T103-NG-03 This spec does not require a specific Swift file layout or type name if the ownership and behavior requirements are met.
  • T103-NG-04 This spec does not reimplement T104 if existing branch work already provides conformant per-stream SBB ownership; implementation must verify branch state first.

Ownership Model

ID State Class Owner
T103-OWN-01 Scroll position, restore phase, restore generation, and persisted anchor facts. Per-stream runtime state keyed by sessionKey.
T103-OWN-02 Scroll-to-bottom button state, last reported hide indicator, and bottom-inset facts used by that control. Per-stream runtime state keyed by sessionKey.
T103-OWN-03 Last-message/unread facts that affect auto-scroll and unread-marker behavior. Per-stream runtime state keyed by sessionKey.
T103-OWN-04 Typing, morph, auto-scroll retry, and debounce work scheduled across an async or dispatch boundary. Captured sessionKey plus generation validation before read or write.
T103-OWN-05 Bubble sizing cache identity when a shared controller-global cache exists. Cache keys include sessionKey; stream cleanup only removes the deleted stream's entries.
T103-OWN-06 Per-stream replay cursors. Transport layer, not ChatViewModel UI runtime state.

Requirements

T103-REQ-01 Single Stream-Switch Seam

Stream activation must pass through one stream-context switch seam. Callers may request a switch, but they must not independently reset scroll, restore, SBB, typing, unread, morph, debounce, or sizing state outside that seam.

T103-REQ-02 Outgoing Flush Uses The Outgoing Key

The switch seam must capture the outgoing sessionKey before rebinding to the incoming stream and must flush outgoing scroll persistence using that captured key. Reading an effective key after mutation for outgoing persistence is invalid.

T103-REQ-03 Seam Work Precedes Offscreen Guards

Required switch bookkeeping must run even when render policy is frozen or the controller is offscreen. Offscreen and frozen guards may skip heavy render work, but they must not skip outgoing flush, incoming restore setup, key commit, timer cancellation, or generation ownership updates.

T103-REQ-04 Debounce Is Batching Only

Debounce timers may batch same-stream work, but they are not lifecycle gates. On stream switch, pending debounce work for the outgoing stream must flush or cancel deterministically. Any callback that survives a yield or dispatch boundary must use a captured sessionKey, not a dynamic "current stream" lookup.

T103-REQ-05 Deferred Work Must Be Stream-Owned

Deferred scroll-to-bottom retries, morph callbacks, typing-state callbacks, and any other scheduled work must capture the owning sessionKey and generation at schedule time and validate both before reading or writing per-stream state.

T103-REQ-06 Shared At-Bottom Definition

SBB hide/show logic, auto-scroll eligibility for appended messages, and restore fallback-to-bottom checks must use one shared at-bottom helper and threshold source. Divergent thresholds across those sites are invalid.

T103-REQ-07 Same-Key Re-Read Is Explicit

A same-key update must not re-arm restore unless forceReReadGeneration advances. Same-key re-read must reload persisted state and must not persist current in-memory geometry until the re-read reaches a confirmed or deterministic fallback state.

T103-REQ-08 Stable Callback Key During Switch

Scroll delegate and layout callbacks during a switch must route through the last committed effective session key for the active surface, not through a dynamic fallback that can change mid-seam.

T103-REQ-09 Deleted Stream Cleanup

When stream membership changes, per-stream runtime entries for deleted keys must be pruned. Timers and work items owned by deleted keys must be cancelled. A later stream reusing the same key starts from a fresh runtime entry unless durable stream data explicitly defines otherwise.

T103-REQ-10 Transport Cursors Are Not UI Runtime State

Per-stream replay cursors belong to the transport owner. UI per-stream runtime state may observe populated messages and scroll facts, but it must not become the owner for replay cursor progression.

Acceptance Checks

  • T103-AC-01 Switching from stream A to stream B persists stream A scroll state using stream A's captured key before stream B becomes the active runtime key.
  • T103-AC-02 Switching into a stream with persisted scroll state restores that position; switching into a stream without persisted scroll state lands at bottom.
  • T103-AC-03 An offscreen or frozen controller still runs switch bookkeeping and does not lose scroll persistence or restore setup.
  • T103-AC-04 A pending debounce callback from stream A cannot mutate stream B after a switch.
  • T103-AC-05 A pending scroll-to-bottom retry from stream A cannot scroll stream B after a switch.
  • T103-AC-06 SBB visibility, appended-message auto-scroll, and fallback-to-bottom decisions use the same at-bottom threshold.
  • T103-AC-07 Same-key updates do not re-arm restore unless forceReReadGeneration advances.
  • T103-AC-08 Same-key re-read does not write stale in-memory geometry into durable persisted scroll state before confirmation or fallback.
  • T103-AC-09 Deleting a stream removes its runtime entry and cancels its owned timers/work items without evicting another stream's active state.
  • T103-AC-10 Shared sizing caches include sessionKey in identity and do not invalidate the visible stream when a different stream is cleaned up.
  • T103-AC-11 Per-stream replay cursors remain owned by the transport layer and are not moved into ChatViewModel UI runtime state.

Implementation Handoff

  1. T103-HO-01 First identify the existing switch seam and state variables that can influence scroll, SBB, restore, unread/last-message, typing, morph, deferred scroll, debounce, and sizing behavior.
  2. T103-HO-02 Consolidate those facts into per-stream ownership keyed by sessionKey or into captured keyed work items where deferred execution is required.
  3. T103-HO-03 Verify existing branch work for T104 before re-implementing SBB state.
  4. T103-HO-04 Keep transport replay cursor work aligned with T100 and T105, but do not move cursor ownership into the T103 UI runtime state.
