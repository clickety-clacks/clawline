T1135 Text Link URL Templates

Self-contained Clawline product and technical specification for turning matched rendered message text into internal-browser links through configurable URL templates. Prepared 2026-05-24 for T1135.

Decision: Clawline message rendering must support user-configurable text-match rules paired with URL templates. T1135 must not ship with a default configured Janus rule; users add rules from Clawline settings, including a Janus/Tracker rule that can open the existing tracker widget URL inside Clawline's internal browser.

The feature belongs at the rendered-message text layer. The renderer owns the final visible text and link ranges; activation routes through Clawline's internal browser surface instead of handing the generated URL to the operating system's external browser.

Goals

  • Allow Clawline to define text-match rules that decorate matching rendered message text as activatable links.
  • Pair each match rule with a URL template that receives the matched text and regex capture groups.
  • Ensure interpolation cannot let matched message text alter the template's scheme, host, path structure, query separators, or fragment separators.
  • Route activation of generated links through Clawline's internal browser surface.
  • Provide a settings UI where users can add, edit, and remove regex plus URL-template rules, including a Janus ticket-reference rule for T123-style references.
  • Keep behavior consistent anywhere assistant or user message text is rendered in Clawline, except for surfaces explicitly scoped out by this spec.
  • Make invalid rule templates and generated URLs fail in a visible, non-crashing way without opening an external browser.

Non-Goals

  • No source-code change, deployment, merge, branch cleanup, or app spindown is specified here.
  • No default configured rule is required or allowed for T1135. Rules are created by the user in settings.
  • No link-preview card is created solely because a generated URL exists. The generated URL is an activation target for the matched text, not new visible message content.
  • No change to explicit markdown links or existing URL detection behavior beyond allowing non-URL text patterns to become links where this spec says they apply.
  • No provider-side message mutation. Generated links are a client rendering and activation behavior only.
  • No external-browser fallback for the T1135 generated-link path.

Terminology

Term Meaning
Match rule A named, configurable rule containing at minimum an enabled flag, a text pattern, and a paired URL template.
Rendered message text The final user-visible text representation after Clawline message parsing, markdown rendering, table rendering, and other presentation transforms have produced linkable text ranges.
Generated link A link range created from a match rule and URL template rather than from a literal URL or explicit markdown link in the message.
URL template A literal URL string with placeholders that are replaced with encoded match values before activation.
Internal browser The Clawline-owned in-app browser surface used for web content opened from chat, such as the existing iOS/iPadOS/Catalyst Safari-view-controller style browser surface. It is not UIApplication.open or an operating-system handoff to an external browser app.
Janus ticket reference A token shaped like T followed by ASCII digits, for example T123 or T1135.

Product Requirements

ID Requirement Acceptance Check
R1135-01 Clawline supports a configurable match rule with a paired URL template. A rule can be represented with a stable ID, enabled/disabled state, regex-compatible match pattern, and URL template, and the renderer can produce a generated link from that rule without hard-coding Janus-only logic into message layout.
R1135-02 Matched text and capture groups are safely interpolated into the template. The full match and every capture group can be referenced from the template, and replacement values are encoded before insertion so message text cannot alter URL delimiters or routing outside the intended template position.
R1135-03 Activation opens the generated URL in Clawline's internal browser, not the external browser. Activating a generated Janus link presents the in-app browser surface with the generated URL. The generated-link path does not call the platform external-open path.
R1135-04 Clawline ships with no configured text-link rules by default. On a fresh install/profile, rendered tokens such as T123 or T1135 do not become generated links until the user adds a matching rule in settings.
R1135-05 Rule behavior is consistent wherever assistant/user message text is rendered, unless the spec explicitly scopes a surface out. The same message content yields the same generated-link ranges and generated activation URLs in transcript bubbles, expanded message views, notification message previews that render assistant/user text, and other Clawline message-text renderers.
R1135-06 Invalid templates and invalid generated URLs fail visibly and safely. An invalid rule does not crash rendering, does not create an invisible dead link, and does not open an external browser. The user or operator receives a visible failure signal appropriate to where the failure is detected.
R1135-07 Settings exposes a rule-management screen for text-link URL templates. The settings screen shows the configured rules as an editable list and includes a + control to add another regex plus URL-template entry.
R1135-08 Users can add as many regex/template rules as they need. The settings UI remains usable as the list grows, with scrolling/list layout that does not overflow fixed panels or hide controls.
R1135-09 Users can delete a configured rule only after confirmation. Each rule row has an x delete control. Activating it opens a confirmation dialog; cancel keeps the rule unchanged, and confirm removes exactly that rule.
R1135-10 A user-created Janus/Tracker rule can use the existing tracker widget URL. After adding regex \bT([0-9]+)\b with template https://tars.tail4105e8.ts.net:19443/tracker.html?id={match}, a rendered T1135 token opens the corresponding tracker widget URL inside Clawline's internal browser.

Rule Contract

A T1135 rule has these semantic fields. Concrete type names are implementation details.

Field Required Meaning
id Stable rule identifier used in diagnostics and tests. User-created rules receive stable generated IDs.
enabled Boolean that controls whether the rule participates in rendering.
pattern Regex-compatible text pattern evaluated against rendered message text.
urlTemplate Absolute internal-browser URL template containing placeholders for match values.

Placeholder Contract

  • {match} and {0} mean the full matched text.
  • {1}, {2}, and later numeric placeholders mean regex capture groups by index.
  • Named capture placeholders may be supported as {name} when the implementation's regex engine exposes named captures.
  • An unresolved placeholder makes the generated URL invalid for that match and must follow R1135-06.

Safe Interpolation

  • The template string is treated as configuration. Matched message text is treated as untrusted input.
  • Each replacement value is URL percent-encoded before insertion into the template.
  • Encoding must preserve the template's literal URL delimiters but must encode delimiters that come from message text, including at least space, slash, question mark, ampersand, equals, hash, percent, and control characters.
  • After interpolation, Clawline constructs a URL object from the full generated string. A string that cannot become a valid absolute URL is invalid.
  • The generated URL must be suitable for Clawline's internal browser surface. The Janus/Tracker example uses an https URL.

Matching Order

  • Rules run against rendered message text ranges that do not already carry an explicit link destination.
  • Explicit markdown links and literal URL-detected link ranges keep their existing activation target.
  • When two generated-link rules overlap the same otherwise-unlinked text range, the earlier enabled rule in configured rule order owns that range.
  • A generated link must not split a Unicode scalar sequence or otherwise create a visually corrupt range.

Janus/Tracker Rule Example

Clawline must not enable this rule by default. This is the expected user-created rule for opening the existing tracker widget from matched ticket text.

{
  "id": "janus-ticket",
  "enabled": true,
  "pattern": "\\bT([0-9]+)\\b",
  "urlTemplate": "https://tars.tail4105e8.ts.net:19443/tracker.html?id={match}"
}
  • T123 generates https://tars.tail4105e8.ts.net:19443/tracker.html?id=T123.
  • T1135 generates https://tars.tail4105e8.ts.net:19443/tracker.html?id=T1135.
  • The visible text remains exactly the matched token, for example T1135. The generated URL is not inserted into the transcript text.
  • The rule is case-sensitive for T1135: T123 matches; t123 does not.
  • A token embedded in a larger word, such as AT123 or T123abc, does not match this example rule because of the word boundary requirement.

Rendering Surface Scope

R1135-05 is intentionally broad because Clawline has multiple message-text renderers. The rule belongs with the rendered-message text pipeline, not only with one transcript cell.

Surface T1135 Requirement
Main transcript assistant/user bubbles Required. Generated Janus links render and activate from normal message text.
Expanded message sheet or expanded message overlay Required. The same rendered message content exposes the same generated-link targets.
Cross-chat notification message previews Required when the preview renders assistant or user message text and supports activation. The generated URL and internal-browser route must match the transcript behavior.
Tables, markdown blocks, inline code, and code blocks inside assistant/user messages Required when they are rendered as selectable or activatable message text. T1135 does not exempt them solely because of markdown styling.
Message accessibility/action surfaces Must not contradict visible behavior. If accessibility exposes link activation for rendered message text, generated links are included with the same destination.
Composer draft text Out of scope. The composer is input text, not rendered assistant/user message text.
Terminal sessions, interactive HTML documents, attachment viewers, settings text, and app chrome Out of scope unless that surface is explicitly rendering assistant/user message text through the Clawline message renderer.

Activation Routing

  • Generated-link activation must enter a Clawline-owned URL-open route that presents the internal browser surface.
  • The generated-link route must be distinguishable in tests from platform external-open APIs.
  • If a platform currently lacks an internal browser surface for the generated URL class, the implementation is not compliant by falling back to external open. It must either provide an internal browser surface or return a visible safe failure under R1135-06.
  • Generated Janus links must not mutate chat state, change the active session, send a prompt, or create a link-preview card. They only navigate the internal browser.

Invalid Rule and URL Behavior

Invalid configuration and invalid generated URLs are product-visible failures, not silent drops.

The implementation should choose the visible surface appropriate to the failure timing: rule-load diagnostics for invalid configured rules, and user-visible activation feedback for a link that fails only after interpolation.

Failure Required Behavior
Invalid regex pattern Disable that rule, keep message rendering stable, and expose a visible diagnostic that names the rule ID.
Unknown placeholder Do not create an activatable link for that match. Expose a visible diagnostic or activation error that names the rule ID.
Missing capture group Do not create an activatable link for that match. The visible matched text remains plain message text.
Generated string is not a valid absolute URL Do not open anything. Show a visible safe failure instead of calling an external browser path.
Internal browser rejects the URL Show a visible safe failure. Do not retry through the external browser.

Minimum Test Matrix

  • Default state: with no user-created rule, T123 and T1135 remain plain rendered text.
  • User-created Janus/Tracker rule: after adding regex \bT([0-9]+)\b, T123 and T1135 match; t1135, AT1135, and T1135abc do not match.
  • Settings list: + adds multiple regex/template entries and the list remains usable when enough entries exist to require scrolling.
  • Delete confirmation: each row's x delete action asks for confirmation; cancel preserves the row and confirm removes exactly that row.
  • Capture/interpolation: a custom rule using {1} constructs the expected URL.
  • Escaping: matched values containing URL delimiter characters are encoded before insertion and cannot add query items, fragments, path segments, or a different host.
  • Existing links: explicit markdown link ranges keep their explicit link destination instead of being overwritten by a generated-link rule.
  • Surface consistency: the same assistant/user message content exposes the same generated URL in at least the main transcript and one secondary message-text surface.
  • Routing: generated-link activation invokes the internal browser route and a test double proves the external-open route was not called.
  • Failure: invalid pattern, unresolved placeholder, invalid generated URL, and internal-browser rejection produce visible safe failures without crashes or external-browser fallback.

Implementation Handoff

  • Implement exactly the T1135 behavior described here: user-configurable match rules, safe template interpolation, no default configured rule, settings add/delete UI, consistent rendered-message coverage, visible safe failures, and internal-browser routing.
  • Place matching at a shared rendered-message text boundary so downstream transcript cells, expanded views, and notification previews consume resolved link ranges instead of rebuilding rule behavior independently.
  • Do not add unrelated URL preview behavior, browser policy changes, message mutation, or provider protocol changes.
  • Preserve explicit link destinations. Generated-link rules fill otherwise-unlinked rendered text ranges.
  • Use the tracker widget URL as the Janus/Tracker example/template value when adding that rule in settings: https://tars.tail4105e8.ts.net:19443/tracker.html?id={match}.
